## Design decision (DECIDED unless marked PROPOSED / REVISABLE)
S1 Mechanism: Review › Imports › [New import] → pick the .xlsx (browser reads it as base64, same as SheetUpdateDrawer;
   server parses with exceljs like sheetUpdate.readUpload — cap raised to 1 MB for this route, REVISABLE) → server builds a
   PREVIEW (nothing written except an hk_import_runs row status 'preview' holding the parsed plan as jsonb, ≤ 2 MB,
   addresses included because it is server-only) → the screen shows per-tab counts and the per-row result table (New /
   Matches existing / Possible duplicate / Warning) → [Commit import] writes everything inside one transaction-like pass
   with an undo set (every created id recorded on the run) → [Undo import] deletes exactly those ids if nothing changed
   since (updated_at check; lead-upload precedent). The parsed plan is deleted from the run row on commit or after 24 h.
S2 Tab → entity map (DECIDED; REVISABLE items marked):
   - Pete Outreach, Jack Outreach → hk_brands segment sponsor_brand, source 'import', import_ref '<tab>:<row>'.
     owner: Jack tab → Jack's profile id; Pete tab → owner_hint 'pete' (new nullable column hk_brands.owner_hint text —
     the ONE migration; Jack runs it) resolved to owner_user_id by a one-time assign when Pete's profile first appears
     (shell.js on his first load, same place his prefs seed). Rows with no Status and no date → status candidate (Pete's
     sourced list; still owner_hint pete — REVISABLE: or unclaimed).
     Website → domain (normalizeDomain). Type: "National CPG" → category "National CPG", is_local false; Jack's Type
     values → notes line "Route: <Type>". Notes / Enrichment Notes / Challenge/Reward Ideas → notes (first), challenge_idea
     (Challenge/Reward Ideas), origin_hook (Enrichment Notes) — each cleanText'd EXCEPT that addresses inside them are
     moved out to contacts when they parse as one, never left in notes.
     Contact / Email → hk_contacts: an address → email (email_source 'import'), name = the brand name + " contact"
     (REVISABLE) unless the cell also has a name; a bare name → contact with no email. Jack tab: Contact = name, Email =
     address → one contact.
     Status + Outreach Date → status + touches (S3). "Jack Outreach" date on a Pete row → an extra touch for Jack
     (sender = Jack, kind outside, channel email, state sent, sent_at = that date).
   - Confirmed Launch Sponsors → relationship founding_partner, status sponsor, hk_sponsor_periods (period 'launch', kind
     launch); notes carry Challenge Name, Raffle Item, Reward, Redemption Method, Discount Code, Percentage Off, Agreement?
     as "Launch: …" lines. Monthly tabs → relationship sponsor (unless already founding_partner), status sponsor,
     hk_sponsor_periods (period 2026-06 … 2026-12, 2027-01; kind monthly; note = Status + Challenge Name); 33 repeated
     names → one brand, many periods. "Septmeber" matched literally. November's Paid? / Amount are NOT imported (no
     pricing or invoice data in Phase 1 — design rule).
   - Non-Profits → segment nonprofit; Chicago Press Hit LIst → segment press; Podcasts → segment podcast (Lane → category,
     Pitch Angle → challenge_idea, Host Email Source → notes). Modules stay off; the rows exist for Phase 3.
   - Events → NOT imported in v1 (not brand-shaped; no 'event' segment). Listed in the preview as "skipped tab" with its
     row count. REVISABLE: widen the segment CHECK with 'event' later.
   - Sheet8 (185 Name + Website) → imported as candidates, segment sponsor_brand, source 'import', import_ref 'Sheet8:<row>',
     unowned, status candidate. PROPOSED — Jack says "skip Sheet8" if that list is not his.
   - "Orgs to Reach Out to", Meliora, Copy of Meliora → skipped (templates / empty).
S3 Status normalization (pure function, unit-tested; unknown text → Review warning "unmapped status", brand stays
   candidate/claimed, text kept in notes; nothing auto-fixed):
   "Email sent M/D" → status sent; touch cold, channel email, state sent, sent_at = M/D/2026 (REVISABLE year rule: the
   year is 2026 unless the cell carries one), created_by system, no Gmail ids; next_due_at = sent_at + bump_after_days.
   "Email drafted M/D" → status drafted; touch cold state drafted, drafted_at = date, no Gmail ids; Review warning "draft
   not linked to Gmail" (the sync cannot follow it) — REVISABLE: status claimed instead.
   "IG DM ready" → status claimed; touch channel ig_dm kind dm_text state drafted.
   "Meeting with … on M/D" → status meeting; "Responded with questions …" / "Replied …" → status replied (no hk_replies
   row — nothing to link); "In" → warning. Multiple dates in Outreach Date → first = cold sent, second = bump sent, third
   = final sent (REVISABLE), each a touch; status from the last. Sponsor-tab Status ("Done", "Need to set up") → period
   note only. Future-dated dates (after today) → warning, imported as given.
S4 Matching inside the import and against hk_brands: normName exact → one brand (merge rows: periods append, contacts
   dedupe by email, notes append, status = the most advanced per the status order candidate < claimed < drafted < sent <
   bumped < final_sent < replied < meeting < signed < sponsor; passed/skipped only if every row says so). Partial (whole-
   word, non-generic) → created separately AND a hk_duplicate_decisions-aware pair listed under Review › Possible
   duplicates — never auto-merged (SALT vs Hogsalt rule). Legacy DB rows (accounts 35 / prospects 14): cross-check only —
   a founding partner present in prospects but missing from the Launch tab → warning; nothing read from them into brands.
S5 Review › Imports screen: runs table (date, source file name, rows read, created, matched, flagged, by whom, [Undo] when
   allowed); [New import] → file picker (.xlsx only) → preview: per-tab card (rows, to create, to match, warnings, skipped)
   + the row table with filters (New / Matches / Possible duplicate / Warning) and the mapped status per row; [Commit
   import] primary / [Cancel]. After commit: toast + links to Brands and Review › Data warnings. Import adds hk_events
   import_committed { run_id, counts } and one brand_created event per brand (no addresses in detail).
S6 Privacy: addresses go ONLY into hk_contacts.email; every other text field is cleanText'd; the preview table shows
   contact presence ("1 contact · has email") never the address; events/logs/reports never carry one; the parsed plan
   lives in the server-only run row and is wiped on commit. Phone numbers: refused (cleanText strips; no phone column).

Landmines (inlined — the coder cannot read project docs):
- inbox/2026-10-26-Chicago_Sponsors.xlsx never leaves inbox/ and is never committed, copied into fixtures, or quoted
  (names + addresses). Tests use invented workbooks built in the test with exceljs.

- HumanKind contact emails: stored, shown only on Brand › Contacts to HK members; never in list rows, previews, events,
  logs, verify shots or reports. Do NOT reuse the HomeLover importer's "@" refusal here; do keep cleanText on free text.
- Fuzzy matches go to Review, never auto-merge. The Sheet is truth after import; no dual-writing; the legacy DB rows are
  cross-check only and get archived later by hk-legacy-cleanup (prospects → projects CASCADE: prospects first).
- Dates: future-dated typos are flagged, never corrected. "Septmeber" matched literally. Pete's column E = Jack's touch.
- outreach_doctrine platform-scope only; voiceExamples / Project outreach_examples separate; Project panel read-only for
  Company Intel; SEGMENT_PASTE_MAX_CHARS is a cap. salesGate untouched; hkGate is the gate; owner role to commit an import
  (REVISABLE: member).
- No pricing / invoice amounts in Phase 1 (skip Paid?, Amount). Mockup data never seeded.
- Jack runs the one migration (owner_hint) in Supabase and replies "ran". Verify scripts never create workspaces/users on
  prod; "restored" checks throw; live runs on prod use an INVENTED mini-workbook, committed then undone, never the real
