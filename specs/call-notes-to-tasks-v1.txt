## Problem
Internal call action items live in Zoom summaries / notes and never reach the shared Goals to-do list,
so Jack and Cyrus re-type them or lose them.

## Design decision (DECIDED unless marked)
- Where: task drawer header → "Paste call notes". Opens a panel: paste text, or upload .txt / .docx / .vtt
  / .md. Optional fields: call date (default today), call title.
- AI extraction (one call): action items with suggested owner (workspace members by name and "I'll…"
  statements; otherwise Unassigned), due date only if stated, suggested Link by name match against the
  workspace's partners, companies, commitments and metric goals, and a 3-line call summary. Never
  invents owners or dates — unknown stays blank.
- Review before anything is created: a checklist of proposed tasks; edit text, owner, due, link;
  untick to drop. Nothing is written until "Create N tasks".
- Creates normal Goals to-dos (sales_week_goals kind 'todo', category "From calls · <date> · <title>",
  this week) through the existing to-do API — they appear in the drawer's "From calls" group, in Goals →
  This week for both people, in the to-do donut and the weekly report. Long items become steps under one
  to-do per topic.
- Each to-do links back to the stored source note (per workspace, members-only, readable from the to-do's
  expanded row). Re-pasting the same notes creates 0 duplicates (hash + similarity check against that
  workspace's existing "From calls" to-dos).
- PROPOSED: the 3-line summary is offered as a draft line for Weekly report §1 notes — Jack keeps or deletes.

## Out of scope
Zoom webhook auto-ingest (follow-on: call-notes-zoom-ingest-v1); Smart Intake's intel filing; any email
or calendar reading (microsoft-connect-v1).

## Standing rules that apply (inlined)
- All writes through the API (FIX-1). Notes text is stored server-side, members-only; never logged in
  full to server logs.
- No phone numbers extracted or stored. Anthropic key server-side only, never printed.
- Respect the existing AI rate limit. Tests that write data restore and report "restored: yes".
  Run test suites one at a time.
