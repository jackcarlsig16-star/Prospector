## Design decision

DECIDED — the partner drop-down tells one story (top to bottom)
1. Status & next step: stage bar, "Last touch: Call · Oct 2 · Jack", days since touch, one suggested next
   action (existing rules), buttons: Next · Log touch · ⋯.
2. People: everyone we know at this partner — from Apollo (Stage 3), from logged touches, from
   known_contacts. Row: name · title · source badge (Apollo / Logged / Sheet) · last activity
   ("Replied Oct 4", "Opened ×3", "Called Oct 2") · email/LinkedIn link icons. "+ Add person" (name, title,
   email optional). Count shown on the Workflow row (👤 3).
3. Activity: one timeline merging touches (manual / apollo / outlook, with source label), stage moves,
   notes, call-notes tasks and flags linked to the partner. Filter chips: All · Emails · Calls & meetings ·
   Notes. Noise hidden by default (hot on/off pairs, snooze+undo pairs, undone events) behind
   "Show all activity (n)".
4. Tasks: linked to-dos (task-drawer link chips), "+ Task" prefilled with the partner link.
5. Intel (collapsed by default, one line preview): angle, role, target titles, sequence + Open in Apollo,
   do-not-say (amber), their words, champion, sources, priority, Open first email.
- "Log touch" form = partner-touch-log-v1 design (date, type, who with suggestions from People, note, stage
  auto/none/pick; never backwards; backdated weeks; undo). "＋ Log touches" bulk catch-up in the Partners
  header with paste-names, review (stage → stage, counting week), apply.

DECIDED — identity: partner domains
- New table partner_domains (business_id, goal_id, domain, is_primary, source: manual|sources|apollo,
  confirmed bool). Seed: parse sources (14) as unconfirmed suggestions; Apollo account name/domain matches
  (11/7) as unconfirmed suggestions. Drop-down Intel gets "Domain(s)" with confirm ✓ / edit / add.
  Only confirmed domains are used for matching. Partners can have several domains (.ai/.io style).
- "Export to Apollo (CSV)" in the Partners header: partners with a confirmed domain that aren't Apollo
  accounts → CSV (company name, domain, category, tier, owner) for Jack to import into Apollo. No Apollo
  writes from Prospector.

DECIDED — partner contacts from Apollo (read-only)
- New table partner_contacts (business_id, goal_id, apollo_contact_id null, name, title, email, linkedin_url,
  source apollo|manual|outlook, first_seen, last_activity_at, last_activity_type). Server-only RLS like other
  sales tables; email stored in DB only (never written to files/logs). No phone numbers.
- Sync: once a day on the first Sync now of the day (and an explicit "Refresh partner people" button),
  for confirmed partner domains that match an Apollo account: pull that account's contacts + their sequence
  status and message events (sent/open real vs bot/click/reply). Capped per run, every Apollo call counted
  and logged; report calls per run. Reuses the existing bot-open rule.

DECIDED — automation (same path for every source)
- Apollo emails to/from partner contacts become touches through the existing touch path
  (applyPartnerSignal, source 'apollo', dedupe on Apollo message id): first email sent → Sent (if behind),
  reply → Replied (if behind). Labeled "from Apollo", undoable, never backwards. Outlook (microsoft-connect
  Stage 3) uses the identical path with source 'outlook' — build the matcher once (by confirmed domain /
  contact email).

PROPOSED / REVISABLE
- Daily cadence + per-run cap number (coder proposes from real call counts). Noise rules for "Show all".
