Q1 Scout today, end to end
1. Mount: App.js:1257 PersistentScout, for every signed-in user on every page; no role gate (Viewer included).
2. Scope: on a workspace page, pills = active business or "All businesses" (PersistentScout.js:98-120);
   accounts come from getAccountsForBusiness (db.js:182-200, `accounts` table by business_id, browser anon
   key). Off-workspace: the legacy territory list (App.js:1127-1130). "All businesses" needs a one-time
   confirm stored on the team user (App.js:1135).
3. Typing: client-side substring match on account NAME only (ScoutCommandBar.js:168-174, max 6) plus 4
   static pages Accounts/Ideas/Pricing/ROI (:26-31). Nothing else is searched: no partners, opps, contacts,
   targets, to-dos, notes, emails, intel. No server search route is called.
4. Ask: buildScoutContext (buildScoutContext.js:55-89) renders every in-scope account as 6-10 lines
   (stage, tier, ACV, close %, compliance from localStorage prospector_compliance :11, last call summary,
   blockers, note, email sentiment from localStorage prospector_threads_cache :52). In scope = layers
   Active Deal/Engaged/Prospecting by default or full territory (scoutLayers.js:8-13, ScoutCommandBar.js:182).
   Size: ~150-250 tokens per account; HomeLover has 66 accounts -> ~10-16k input tokens per ask (estimate,
   not measured - nothing logs it). Follow-ups resend the last 6 turns (:264).
5. Model: MODELS.STANDARD = claude-sonnet-4-6 (models.js:9), max_tokens 2000, streamed
   (ScoutCommandBar.js:202-210) through POST /proxy/anthropic/messages.
6. Server: proxy forwards req.body verbatim to Anthropic with the server key (server.js:58-67); auth =
   sessionAuth cookie (server.js:29, authUser.js:8,14-20) + anthropicRateLimit 60/h member, 600/h platform
   owner, in-memory (requireAuth.js:124-137). It only console.logs model/status (server.js:73). No usage
   row: business_anthropic_usage is written only by the server-side callAnthropic path
   (api/businesses/shared.js:56), never by the proxy. Cost per Scout call is therefore unknown.
7. Links: the response's account names are matched back to buttons (ScoutActionButtons.js:10-24, :102-103)
   -> onNav('accounts', id). navTo drops the id: App.js:1225-1229 only uses the second arg for tools, so
   a click opens the Accounts LIST, not the account. "Open in Ledger" -> navTo('ledger'); 'ledger' is not
   in VISIBLE_PAGES (App.js:76) so it lands on Workspaces; the page==="ledger" branch (App.js:1316) and
   ledger/ScoutModal.js are unreachable. "+ Add Task" writes the legacy tasks state (App.js:1270), not
   sales_week_goals.
8. Security: the browser decides system prompt, model and max_tokens; any signed-in user can send any body
   to Anthropic within the hourly cap (noted REVISABLE at requireAuth.js:121). The API key never reaches the
   browser. Context sent includes call summaries and compliance from localStorage. Basic Auth remains as an
   emergency gate (server.js:17, basicAuth.js:19-22).

Verdict: reuse vs rebuild
Scout's shell (one persistent mount, compact/plain modes, palette, response panel, recent queries) is
reusable as the UI. Its "search" is not: it is a name filter over one table plus a pipeline-brief prompt
whose context, links and task writer are all tied to the legacy accounts model. "Search everything" needs
a new server route + per-record navigation; the AI ask can later sit on top of that route's results
instead of a whole-pipeline dump.
